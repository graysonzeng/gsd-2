# v1.2 Scout Fan-out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `feat/phase-discipline-preset-v1` 上为 `phase-discipline-8step` 落地 P1 `research-slice` scout fan-out：在 dispatch 前并行运行 3 个 scout subagent，合并结果写入 canonical slice research artifact，并让 auto-loop 自然推进到后续 `plan-slice`，同时把 kernel 侵入压到最低。

**Architecture:** 选择 handoff §4.1 的 **方案 C**，而不是 A/B/D。具体做法是：不新增通用 `PreDispatchHookConfig.action: "fan-out"`，而是在 preset-owned builtin pre-dispatch hook 上返回新的结构化 `fanOutSpec`，由 `auto/phases.ts::runDispatch()` 消费并短路执行 `phase-discipline/scout-fanout.ts`。`auto-dispatch.ts` 保持不动，`honour-phase-discipline-advice` 语义保持原样；新的 fan-out 只拦截 canonical `research-slice`（`Mxxx/Syy`），不拦截 `research-milestone` 和 `parallel-research-slices` (`Mxxx/parallel-research`)。

**Tech Stack:** TypeScript、现有 `pre_dispatch_hooks` / `RuleRegistry` / `runDispatch()` 管线、`shared-harness/subagent-spawn.ts`、Node test runner (`node --test` via `resolve-ts.mjs`)。

## 0. 先决结论与方案选型

### 0.1 已核实的 live-code 事实

- `runDispatch()` 才是 `PreDispatchResult` 的真实消费方；它当前只理解 `skip / replace / advise / proceed`，并在 advice 场景做一次二次 `resolveDispatch(...)`。
- `rule-registry.ts::evaluatePreDispatch()` 当前是 **同步组合器**，不是 async executor；它可以返回结构化结果，但不适合直接执行 fan-out side effect。
- `auto-dispatch.ts` 当前已经有 `honour-phase-discipline-advice` prefix rule；这是 v1 skeleton 的 advisory path，v1.2 不应重新打开。
- `phase-discipline` 当前已经有 builtin pre-dispatch (`profile-dispatch`) 与 builtin post-unit (`reviewer-hook` / `impl-plan-validator` / `verify-fuse`) 先例，说明“preset-owned builtin + narrow runtime bridge”是该分支的既有做法。
- `shared-harness/subagent-spawn.ts` 已提供稳定的 `spawnGsdSubagent()` / terminal parsing / timeout / process cleanup 行为，应该直接复用。
- `feat/composed-lite-runtime-owned:.../p1-research.ts` 证明有效参考实现是：固定 3 个 scout、`Promise.all(...)` fan-out、guard prompt、`--tools read,grep,find,ls,bash`、raw log、审计、全部成功后再写 merged artifact。

### 0.2 A/B/C/D 评估

| 方案 | 结论 | 理由 |
|---|---|---|
| A. 新增通用 `action: "fan-out"` | 不选 | 需要把 pre-dispatch authoring grammar、validator、registry、engine 一起扩面；还会把原本同步的 pre-dispatch 语义往 async/executor 方向推，属于过度 kernel 化。 |
| B. `after: ["research-slice"]` post-unit hook | 不选 | 语义时序错误。fan-out 必须发生在 research dispatch 前，否则只能“评审 research 结果”，不能替代 research 生产过程。 |
| C. `PreDispatchResult` 新增 `fanOutSpec` | **选中** | 保持“dispatch 前执行”的正确语义，同时把 kernel delta 限定在结果 contract 和 `runDispatch()` 消费侧；不需要改 `auto-dispatch.ts` 和用户 authoring grammar。 |
| D. 滥用 `replace` + builtin 短路 | 不选 | 会把 fan-out 伪装成假 unit / hook unit，污染 unit-type 语义、artifact path、stuck detection 和测试面，整体风险高于 C。 |

### 0.3 选型后的具体落点

采用 **C 的 builtin 变体**：

- **不新增**新的 `PreDispatchHookConfig.action` 字面量。
- 新增 preset-owned pre-dispatch hook `phase-discipline-scout-fanout`。
- 该 hook 继续使用现有可通过校验的 action 作为“carrier”，但真正行为由 `hook.builtin` 驱动。
- carrier action 显式定为 `modify`：即使未来 builtin marker 被误删，也只会退化成无副作用 modify，而不会把 `research-slice` 错误 advise 到其它 unit。
- `rule-registry.ts` 对该 builtin 返回 `{ action: "proceed", fanOutSpec, ... }`。
- `runDispatch()` 在 **完成最终 unit 选择、stuck detection、prior-slice guard 之后**，检测 `fanOutSpec` 并执行 `runPhaseDisciplineScoutFanOut(...)`。
- fan-out 成功后直接写 canonical `S##-RESEARCH.md`，然后 `return { action: "continue" }`；下一轮 state derivation 会自然跳过 `research-slice`，落到 `plan-slice`。

这个设计满足 handoff 的 6 条纪律：独立 track、最小 kernel 侵入、不破坏 advice、复用 shared harness、观测面对齐、且认真评估并偏离了 spec 原始 A 案。

## 3. 关键实现细节（供实现时锁边界）

### 3.1 `PreDispatchResult` contract 只加一个新能力

在 `types.ts` 添加：

```ts
export interface PreDispatchFanOutSpec {
  builtin: string;
  unitType: string;
  unitId: string;
  model?: string;
  provider?: string;
  scouts: Array<{
    focus: "codebase_scan" | "constraints_risks" | "prior_art";
    task: string;
  }>;
}

export interface PreDispatchResult {
  action: "proceed" | "skip" | "replace" | "advise";
  prompt?: string;
  unitType?: string;
  unitId?: string;
  advisedUnitType?: string;
  advisedUnitId?: string;
  model?: string;
  /** Only valid when action === "proceed". Non-proceed actions must not carry fanOutSpec. */
  fanOutSpec?: PreDispatchFanOutSpec;
  firedHooks: string[];
}
```

约束：

- **不**新增新的 `action` 字面量
- `fanOutSpec` 只能由 builtin pre-dispatch hook 生成
- `fanOutSpec` 只能与 `action === "proceed"` 共存；`skip / replace / advise` 一律不得携带它
- `fanOutSpec` 只用于 engine consumption，不暴露成新的用户 authoring grammar
- `PreDispatchFanOutSpec.builtin` 在 kernel contract 中保持 `string`，具体 marker 常量只放在 `phase-discipline/preset.ts`

### 3.2 pre-dispatch builtin 组合语义要升级，但只在 `rule-registry.ts`

当前 `evaluatePreDispatch()` 遇到 builtin profile dispatch 会直接 return；这在只有一个 builtin 时没问题，但 v1.2 需要两个 builtin pre-hooks 串联：

1. `phase-discipline-profile-dispatch`
2. `phase-discipline-scout-fanout`

必须改成以下语义：

- builtin 返回 `skip / replace / advise`：立即 return
- builtin 返回 `proceed`：将其对 `prompt / model / fanOutSpec` 的附加结果合并到当前 accumulator，然后继续处理后续 hooks
- 最终若没有终止类 action，返回 `{ action: "proceed", prompt, model, fanOutSpec, firedHooks }`

建议实现形态：

```ts
if (hook.builtin === PHASE_DISCIPLINE_PRESET_HOOK_NAMES.profileDispatch) {
  const result = evaluatePhaseDisciplineProfileDispatch(...);
  firedHooks.push(hook.name);
  if (result.action !== "proceed") return { ...result, firedHooks };
  currentPrompt = result.prompt ?? currentPrompt;
  currentModel = result.model ?? currentModel;
  continue;
}

if (hook.builtin === PHASE_DISCIPLINE_PRESET_HOOK_NAMES.scoutFanOut) {
  const result = evaluatePhaseDisciplineScoutFanOut(...);
  firedHooks.push(hook.name);
  if (result.action !== "proceed") return { ...result, firedHooks };
  currentPrompt = result.prompt ?? currentPrompt;
  currentModel = result.model ?? currentModel;
  currentFanOutSpec = result.fanOutSpec ?? currentFanOutSpec;
  continue;
}
```

这一步是整个 C 案能成立的关键。

同时要把以下回归风险作为一级 test invariant 锁死：

- `profile-dispatch` 返回 `advise` 时仍然立即 return，不会继续跑 `scout-fanout`
- `profile-dispatch` 返回 `proceed` 时才允许继续组合后续 builtin
- builtin `proceed` 接入累加路径后，`builtin proceed → user modify` 与 `user modify → builtin proceed` 的 prompt/model 组合顺序都不能悄悄变化

### 3.3 `scout-fanout.ts` 分成 evaluator 和 executor 两层

建议 API：

```ts
export function evaluatePhaseDisciplineScoutFanOut(input: {
  unitType: string;
  unitId: string;
  prompt: string;
  basePath: string;
  hookConfig?: PreDispatchHookConfig;
}): PreDispatchResult

export async function runPhaseDisciplineScoutFanOut(input: {
  basePath: string;
  unitType: string;
  unitId: string;
  fanOutSpec: PreDispatchFanOutSpec;
  spawnImpl?: typeof spawnGsdSubagent;
}): Promise<{ researchArtifactPath: string; scoutCount: number; rawLogDir: string }>
```

`evaluate...` 只做判定与 spec 组装：

- `unitType !== "research-slice"` → `proceed`
- `unitId` 不是 `Mxxx/Syy`（例如 `M001/parallel-research`）→ `proceed`
- canonical research artifact 已存在 → `proceed`
- 否则返回 `fanOutSpec`

其中 `fanOutSpec.model/provider` 的来源需要显式固定：优先 hook 自身 `model/provider`，否则保留为空并让 executor 走共享的 subagent model 解析/回退路径。

`run...` 才做 side effects：

- 解析 `unitId -> mid/sid`
- 从 roadmap / state helper 取 slice title
- 生成 3 个 scout 任务
- 写 guard prompt 临时文件
- `Promise.allSettled()` fan-out `spawnGsdSubagent()`
- guard prompt 文本直接对齐 composed-lite `p1-research.ts` 的 `SCOUT_GUARD_PROMPT` 约束：忽略 generic startup / skill discovery，避开 `.agents` / `~/.agents` / user-global skills
- 所有 scout 成功后，再原子写 canonical `S##-RESEARCH.md`
- 写 `.phase-discipline/<stem>.json`
- 写 `.phase-discipline/<stem>-scout-<focus>-stdout.log` / `stderr.log`
- 任一 scout 失败：
  - 立即取消/清理其他仍在运行的 scout child process，避免失败后后台残留继续跑
  - **不创建 canonical `RESEARCH.md`**
  - 仍保留 raw logs / observability
  - 抛出错误给 `runDispatch()`

### 3.4 scout 配置与 prompt 决策

固定 3 个 scout：

```ts
const SCOUT_TASKS = [
  { focus: "codebase_scan", task: "..." },
  { focus: "constraints_risks", task: "..." },
  { focus: "prior_art", task: "..." },
] as const;
```

约束继承 composed-lite：

- 使用临时 `SCOUT_GUARD_PROMPT`
- child CLI 参数：`--append-system-prompt <file> --tools read,grep,find,ls,bash`
- guard prompt 明确禁止 `.agents` / `~/.agents` / user-global skills / 泛化技能发现

模型决策：

1. 若 hook 配置了 `provider + model`，使用它
2. 否则尝试现有 subagent model 解析路径
3. 最后才回退当前 session model

v1.2 **不**做 per-scout model fan-out；这是 deliberate scope cut。

### 3.5 artifact 与 observability 决策

canonical research artifact：

- 路径：现有 `resolveSliceFile(basePath, mid, sid, "RESEARCH")` 对应文件
- 内容：markdown brief 即可，不引入 YAML schema
- 结构建议：

```md
# Slice Research

- Source: phase-discipline scout fan-out
- Slice: M001/S01 <title>
- Scouts: codebase_scan, constraints_risks, prior_art

## Codebase Scan
...

## Constraints & Risks
...

## Prior Art
...
```

observability：

- 目录：该 slice 目录下 `.phase-discipline/`
- JSON：记录 hook 名、unit、scout 列表、模型、开始/结束时间、每个 scout 的 status / outputChars / error / raw log path
- Raw logs：每个 scout 各自 stdout/stderr 文件

这样与 reviewer hook 的 OQ-7 / OQ-10 现有风格对齐，同时不污染 `.gsd/composed-lite/logs/raw/`。

### 3.6 `runDispatch()` 的消费位置必须靠后，不可提前

`runDispatch()` 的 fan-out 分支必须放在：

1. 首次 `resolveDispatch()`
2. `runPreDispatchHooks()`
3. advisory replace/advise 处理
4. `dispatch-match` event
5. stuck detection
6. prior-slice blocker
7. **然后才执行 fan-out short-circuit**

这样能保持：

- final selected unit 仍然驱动 stuck detection / blocker 判断
- 不绕开现有 guardrails
- `honour-phase-discipline-advice` 的现有不变量不被破坏

fan-out 成功后的控制流：

```ts
await runPhaseDisciplineScoutFanOut(...)
ctx.ui.notify(...)
return { action: "continue" }
```

不要返回 `next`，也不要伪造一个新 unit 去跑 `runUnit()`。

消费守卫必须写成 `preDispatchResult.action === "proceed" && preDispatchResult.fanOutSpec`，不要让 non-proceed action 与 fan-out 分支发生隐式耦合。

### 3.7 失败语义

当任一 scout 失败：

- 不写 canonical `RESEARCH.md`
- `runDispatch()` 记录 warning + pause auto
- 返回 `break`
- 不创建 fake research artifact
- 下次 resume 时允许再次尝试同一个 `research-slice`

不要做“部分成功 + 继续推进”的宽松模式；这会把 P1 质量退化成随机。

## 5. 风险与防错清单

### 5.1 最大实现风险

- **builtin pre-dispatch 组合顺序**：如果还保持“builtin 一律立即 return”，则 `profile-dispatch` 会吞掉后续 scout-fanout hook。
- **错误写入 canonical artifact**：若先写 `RESEARCH.md` 再发现某个 scout 失败，会让 scheduler 错误跳过 research。
- **误伤 parallel research**：`M001/parallel-research` 必须显式 bypass。
- **把 fan-out 放到 wrong stage**：若在 `runDispatch()` 太早 short-circuit，会绕过 prior-slice blocker / stuck detection。

### 5.2 必须锁死的实现不变量

- `auto-dispatch.ts` 不改
- `PreDispatchHookConfig.action` 不扩面
- `research-milestone` 不改
- `parallel-research-slices` 不改
- fan-out 成功后写的是 canonical slice `RESEARCH` 文件，而不是新造 side artifact
- 失败时不得留下成功假象 artifact

### 5.3 如果中途发现这些情况，停止并重审方案

- 需要修改 `preferences-validation.ts` 才能表达 v1.2 authoring surface
- 需要给 `auto-dispatch.ts` 增加新的 dispatch rule 才能跑通
- 需要给系统引入一个新的 unit type 才能完成 short-circuit
- 需要把 `shared-harness/subagent-spawn.ts` 改造成 phase-discipline 专用版本

这些都说明已经偏离选中的 C 案。
