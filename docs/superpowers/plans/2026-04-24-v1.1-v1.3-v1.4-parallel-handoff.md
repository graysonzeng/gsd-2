## 三、v1.1 Admission — 独立会话指南

### 目标

在 P0 阶段（`discuss-milestone` 完成后）运行 admission-checklist post-unit hook，验证 milestone 是否具备开始条件。

### Spec 来源

- `docs/superpowers/specs/phase-discipline-preset.md` §12 v1.1 行
- `docs/superpowers/roadmap/phase-discipline-roadmap.md` §3

### 实现形态（spec §12）

> New post-unit hook `phase-discipline-admission` with 6–8 checklist items; `retry_on` pattern if checklist has unchecked items

### 具体步骤

1. **`preset.ts`** — 在 `phaseDiscipline8StepPostUnitHooks` 数组中新增 hook：
   ```typescript
   {
     name: "phase-discipline-admission",
     after: ["discuss-milestone"],
     prompt: "...", // 6-8 项 checklist，检查 milestone 是否具备开始条件
     artifact: "ADMISSION-CHECKLIST.md",
     retry_on: "ADMISSION-RETRY.md",
     max_cycles: 2,
   }
   ```
2. **`PHASE_DISCIPLINE_PRESET_HOOK_NAMES`** — 添加 `admission: "phase-discipline-admission"`
3. **Prompt 设计**（核心）：prompt 应要求 agent 检查：
   - milestone 目标是否明确（有具体 deliverable）
   - 依赖项是否就绪（无 blocking 前置 milestone）
   - scope 是否合理（不超过 5 个 slice）
   - 验收标准是否可测（有 verification 命令或手动验收步骤）
   - 风险是否已识别
   - milestone 估算是否合理
   然后输出 markdown checklist（`- [x]` / `- [ ]`）。如果有 unchecked 项，写 `ADMISSION-RETRY.md` 触发 retry。
4. **测试**：在 `phase-discipline/tests/` 新增 `admission.test.ts`
   - 测试 hook 通过 preset merge 正确注入
   - 测试 prompt 执行后能生成 checklist artifact
   - 测试 unchecked 项触发 retry
5. **不需要改动**：`profile-map.ts`（P0 已经是 soft gating）、`rule-registry.ts`、`reviewer-hook.ts`

### 风险（roadmap §3.3）

- checklist 空洞化 / 直接照搬 composed-lite 文案 → prompt 需仔细设计，与 composed-lite `phases/p0-admission.ts` 对比但不照搬

### 退出标准

- ✅ 新增测试通过
- ✅ typecheck 通过
- ✅ 现有 58 测试不回归

## 四、v1.3 Impl-plan Validator — 独立会话指南

### 目标

在 P2→P3 边界验证 `plan-slice` 输出的实现计划 YAML 符合增强 schema（含 `rollback_hint`、`acceptance`、`files[]`），并将 P2/P3 gating 从 soft 升级为 strict。

### Spec 来源

- `docs/superpowers/specs/phase-discipline-preset.md` §12 v1.3 行
- §3.1b 表格 P2/P3 列的 "v1.3: impl-plan-YAML validator"

### 实现形态（spec §12）

> Tighten `gsd_plan_slice` schema to require `rollback_hint`, `acceptance`, `files[]` per task; post-unit hook validates

### 具体步骤

1. **新文件 `phase-discipline/impl-plan-validator.ts`** — 导出验证函数：
   ```typescript
   export interface ImplPlanValidationResult {
     valid: boolean;
     errors: string[];
   }
   export function validateImplPlan(planContent: string): ImplPlanValidationResult
   ```
   验证 plan-slice 输出中每个 task 包含：
   - `rollback_hint: string`（回滚提示）
   - `acceptance: string`（验收标准）
   - `files: string[]`（预期修改文件列表）
2. **`preset.ts`** — 新增 post-unit hook：
   ```typescript
   {
     name: "phase-discipline-impl-plan-validator",
     after: ["plan-slice"],
     prompt: "Validate the implementation plan...",
     artifact: "IMPL-PLAN-VALIDATION.md",
     retry_on: "IMPL-PLAN-RETRY.md",
     max_cycles: 2,
   }
   ```
3. **`PHASE_DISCIPLINE_PRESET_HOOK_NAMES`** — 添加 `implPlanValidator: "phase-discipline-impl-plan-validator"`
4. **`profile-map.ts`** — 更新 P2 和 P3：
   ```typescript
   // P2: gating 改为 "strict", 添加 completionArtifact
   { phase: "P2", units: ["plan-slice", "refine-slice"], gating: "strict",
     completionArtifact: ".gsd/milestones/{mid}/slices/{sid}/IMPL-PLAN-VALIDATION.md" },
   // P3: gating 改为 "strict", 同上
   { phase: "P3", units: ["plan-slice"], gating: "strict",
     completionArtifact: ".gsd/milestones/{mid}/slices/{sid}/IMPL-PLAN-VALIDATION.md" },
   ```
5. **测试**：
   - `phase-discipline/tests/impl-plan-validator.test.ts` — 验证 schema 检查逻辑
   - 确认 profile-dispatch 在 P2/P3 strict gating 下正确阻止跳过
6. **`preferences-validation.ts`** — 无需改动（用既有 post-unit hook 验证路径）

### 风险（roadmap §3.3）

- schema 一次收得过死 → 仅 require `rollback_hint`/`acceptance`/`files[]`，不验证内容质量
- 字段只要"存在"不要"质量" → v1.3 scope 仅做 structural validation

### 退出标准

- ✅ 新增测试通过
- ✅ P2/P3 gating 改为 strict 后 profile-dispatch 测试仍通过（或更新现有测试）
- ✅ typecheck 通过
- ✅ 现有 58 测试不回归

## 五、v1.4 Verify-fuse — 独立会话指南

### 目标

当 `validate-milestone` 失败时，阻止 milestone close（而非当前的 carry-forward 行为），实现 P5 strict 验证。

### Spec 来源

- `docs/superpowers/specs/phase-discipline-preset.md` §12 v1.4 行
- §3.1b 表格 P5 列

### 实现形态（spec §12）

> Preference `verify_fuse_on_fail?: boolean`; when true, `validate-milestone` failure blocks milestone close instead of carry-forward

### 具体步骤

1. **`preferences-types.ts`** — `GSDPreferences` 新增字段：
   ```typescript
   verify_fuse_on_fail?: boolean;
   ```
   同时在 `KNOWN_PREFERENCE_KEYS` 数组中添加 `"verify_fuse_on_fail"`
2. **`preferences-validation.ts`** — 添加验证：
   ```typescript
   if (preferences.verify_fuse_on_fail !== undefined) {
     if (typeof preferences.verify_fuse_on_fail === "boolean") {
       validated.verify_fuse_on_fail = preferences.verify_fuse_on_fail;
     } else {
       errors.push("verify_fuse_on_fail must be a boolean");
     }
   }
   ```
3. **新文件 `phase-discipline/verify-fuse.ts`** — 导出函数：
   ```typescript
   export function shouldBlockMilestoneClose(input: {
     basePath: string;
     milestoneId: string;
     validationPassed: boolean;
   }): { blocked: boolean; reason?: string }
   ```
   读取 preferences，当 `verify_fuse_on_fail === true` 且 `validationPassed === false` 时返回 `blocked: true`
4. **`preset.ts`** — 新增 post-unit hook（在 `validate-milestone` 后触发）：
   ```typescript
   {
     name: "phase-discipline-verify-fuse",
     after: ["validate-milestone"],
     prompt: "Check if milestone validation passed. If verify_fuse_on_fail is enabled and validation failed, block milestone close.",
     artifact: "VERIFY-FUSE.md",
     retry_on: "VERIFY-FUSE-RETRY.md",
     max_cycles: 1,
   }
   ```
5. **`PHASE_DISCIPLINE_PRESET_HOOK_NAMES`** — 添加 `verifyFuse: "phase-discipline-verify-fuse"`
6. **`profile-map.ts`** — P5 gating 可选升级（当 `verify_fuse_on_fail=true` 时）：
   - 方案 A（简单）：P5 仍为 soft，fuse 逻辑全在 post-unit hook 中
   - 方案 B：P5 gating 改为 conditional strict（依赖 preference）
   - **推荐方案 A**（保持 profile-map 不变，逻辑在 hook 中实现）
7. **测试**：
   - `phase-discipline/tests/verify-fuse.test.ts` — 验证 fuse 逻辑
   - preference 开启/关闭两种路径
   - validation pass / fail 组合

### 风险（roadmap §3.3）

- 默认开太早 → `verify_fuse_on_fail` 默认为 `false`（需 opt-in）
- 上游输入质量不足时放大噪音失败 → 仅在 `validate-milestone` 有明确失败信号时触发

### 退出标准

- ✅ 新增测试通过
- ✅ preferences validation 正确处理新字段
- ✅ typecheck 通过
- ✅ 现有 58 测试不回归
